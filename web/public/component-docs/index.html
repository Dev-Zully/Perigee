    Composition patterns

    Library pieces are designed to be combined. These patterns are used across the app:

    Loading button

    Buttons that trigger async work stay focusable and announce progress: set aria-busy, keep the label, and put a Spinner in the leading slot.

    <Button aria-busy={saving} disabled={saving}>
  {saving ? <Spinner size="sm" color="white" /> : null}
  {saving ? 'Saving…' : 'Save'}
</Button>

    Table inside a card

    DataTable owns its own border, so render it inside CardContent with the card chrome disabled by passing className="border-0" — this keeps one border per surface.

    <Card>
  <CardHeader>
    <CardTitle>Vaults</CardTitle>
  </CardHeader>
  <CardContent>
    <DataTable columns={columns} data={vaults} pageSize={10} className="border-0" />
  </CardContent>
</Card>

    Status pill in a table cell

    Use a ColumnDef.cell renderer to map a row value to a Badge variant instead of styling the cell directly.

    const columns: ColumnDef<Vault>[] = [
  { key: 'name', header: 'Name', sortable: true },
  {
    key: 'status',
    header: 'Status',
    cell: (vault) => (
      <Badge variant={vault.status === 'healthy' ? 'success' : 'warning'}>
        {vault.status}
      </Badge>
    ),
  },
];

    Announce the result of an action

    Keep a live region mounted for the lifetime of the screen and change only its message — a region that mounts with its text is frequently not announced.

    <LiveStatus message={status} />
<Button onClick={runAnalysis} aria-busy={running} disabled={running}>
  {running ? 'Analysing…' : 'Analyse'}
</Button>

    Accessibility baseline

    Every component below is documented with its own accessibility notes. The shared rules are:

    • Native elements first — Interactive primitives render real <button>, <input>, <a>, and <table> elements so keyboard support, focus handling, and browser semantics come for free.
    • Visible focus is never removed — Every focusable component paints a focus-visible ring in the brand cyan. Do not override outline when composing these primitives.
    • Announce dynamic changes — Async results are announced through LiveStatus (polite) and LiveAlert (assertive) rather than relying on colour or layout changes.
    • Colour is never the only signal — Status colour pairings are contrast-audited (≥ 4.5:1) and always paired with a text label.
    • Reduced motion is respected — A global prefers-reduced-motion rule disables decorative animation, so animated components must also expose a non-motion cue.

    Versioning

    These docs are versioned with the web app: this page describes v0.1.0, matching the version field in web/package.json.

    npm run docs:release freezes the current output under versions/<version>.json and publishes a versioned snapshot of the docs site, so older releases stay browsable. Breaking changes are recorded per release in the migration guide.

    Maintaining these docs

    Add the component to scripts/docs/registry.mjs, write JSDoc on the component and its props interface, then run npm run docs:build. The generated files live in web/docs/components.

    Want to documentWrite
    Prop descriptionJSDoc above the prop in the props interface
    Default valueinline default in destructuring, or @default
    Usage example@example above the component
    Accessibility notes@accessibility above the component
    Composition guidance@composition above the component
    Deprecation and replacement@deprecated above the component
    Breaking changescripts/docs/breaking-changes.json

    npm run docs:check fails when any generated file is stale, so these docs cannot silently drift from the code.
