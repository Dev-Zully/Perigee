    v0.1.0

    First published cut of the shared component library: the ui/ primitives became the documented public surface.

    Button replaced CommonButton

    Severity: breaking · Affected component: button

    components/common/Button is superseded by components/ui/Button. variant="primary" became variant="default", the loading prop folded into the native disabled attribute, and a size prop was added.

    Before — CommonButton

    Removed or changed in the new API — CommonButton from components/common/Button/Button.tsx

    PropTypeDefaultRequiredDescription
    variant"primary" | "secondary" | "outline""primary"No—
    loadingbooleanfalseNo—
    …restReact.ButtonHTMLAttributes<HTMLButtonElement>——Spread onto the underlying <button>. Any native attribute not listed above is forwarded verbatim.

    After — Button

    Current API — Button from components/ui/Button.tsx

    PropTypeDefaultRequiredDescription
    variant"default" | "destructive" | "outline" | "secondary" | "ghost" | "link""default"NoVisual treatment. "default" is the cyan brand action; "destructive" is reserved for irreversible actions; "link" renders text-only styling.
    size"default" | "sm" | "lg" | "icon""default"NoControl height and padding. "icon" is a square control for a single glyph.
    asChildbooleanfalseNoAccepted for Radix-style API parity but not implemented yet: the component always renders a <button>. Kept optional so callers migrating from shadcn-based snippets do not fail type checking.
    …restReact.ButtonHTMLAttributes<HTMLButtonElement>——Spread onto the underlying <button>. Any native attribute not listed above is forwarded verbatim.

    Call-site migration

    Before:

    <CommonButton>Save</CommonButton>

    After:

    <Button>Save</Button>

    Before:

    <CommonButton variant="primary">Save</CommonButton>

    After:

    <Button variant="default">Save</Button>

    Before:

    <CommonButton variant="secondary">Cancel</CommonButton>

    After:

    <Button variant="secondary">Cancel</Button>

    Before:

    <CommonButton variant="outline">Back</CommonButton>

    After:

    <Button variant="outline">Back</Button>

    Before:

    <CommonButton loading>Saving…</CommonButton>

    After:

    <Button disabled aria-busy>Saving…</Button>

    Notes

    • CommonButton set disabled whenever loading was true, so the disabled mapping preserves behaviour exactly.
    • size, ghost, link, and destructive variants exist only on Button.
    • Update the import path as well as the JSX: components/common/Button/Button → components/ui/Button.

    Codemod

    sed -i "s#components/common/Button/Button#components/ui/Button#g; s#\bCommonButton\b#Button#g" $(git ls-files '*.tsx' '*.ts')

    Ad-hoc status pills replaced by Badge

    Severity: breaking · Affected component: badge

    Per-screen pill markup was consolidated into Badge, which owns the colour variants and the audited contrast pairings. The previous badge--green / badge--red classes were removed.

    After — Badge

    Current API — Badge from components/ui/Badge.tsx

    PropTypeDefaultRequiredDescription
    variantBadgeVariant"default"NoSemantic colour pairing. Every variant is contrast-audited (see below).
    children (required)React.ReactNode—YesShort label text — keep it to one or two words so the pill stays compact.
    classNamestring—NoExtra Tailwind classes merged after the variant classes.

    Call-site migration

    Before:

    <span className="badge--green">Passed</span>

    After:

    <Badge variant="success">Passed</Badge>

    Before:

    <span className="badge--red">Over budget</span>

    After:

    <Badge variant="danger">Over budget</Badge>

    Before:

    <span className="badge--amber">Pending</span>

    After:

    <Badge variant="warning">Pending</Badge>

    Notes

    • Badge has no size prop — density is inherited from the surrounding text.
    • Colour is never the only signal: keep a text label inside the pill (WEB-38 / #492).

    Handling a deprecation

    @deprecated in JSDoc automatically raises a banner on the component page and links the replacement. Use it together with an entry in scripts/docs/breaking-changes.json so consumers get a mechanical migration, not just a warning.
