# REST API and OpenAPI

The API is described by an OpenAPI document generated by `utoipa` and served at
`/api-docs/openapi.json` (Swagger UI at `/swagger-ui`). `core/src/rest_api.rs` turns that
document into the published contract.

## Conventions

* **Versioning in the URL**: every route is available under `/v1/...` (see
  `api_versioning.rs`). The published spec lists `/v1` as its server.
* **Errors are RFC 7807** (`application/problem+json`): `type`, `title`, `status`,
  `detail`, `instance`, plus extensions such as `errors` for field-level validation.
  Build them with `ProblemDetails::from_status(...)`.
* **Pagination** is cursor based; see `PAGINATION.md`. List endpoints take `limit` and
  `cursor`.
* **Idempotency**: mutating endpoints accept `Idempotency-Key`; see `IDEMPOTENCY.md`.

## Tooling

`openapi-tools` (a binary in `Perigee-core`) post-processes the raw document:

```bash
curl localhost:3000/api-docs/openapi.json > raw.json
cargo run -p Perigee-core --bin openapi-tools -- prepare raw.json openapi.json --version v1
cargo run -p Perigee-core --bin openapi-tools -- check openapi.json
cargo run -p Perigee-core --bin openapi-tools -- postman openapi.json perigee.postman_collection.json
```

* `prepare` upgrades the `utoipa` 3.0 output to OpenAPI **3.1** (`nullable` becomes a type
  union with `null`, `example` becomes `examples`, boolean `exclusiveMinimum` becomes a
  number), adds the shared `Problem` schema and points every `4xx`/`5xx` response at it.
* `check` fails when the spec breaks the contract: not 3.1, no `Problem` schema, an
  operation without a unique `operationId` or a tag, an error response that is not
  `problem+json`, or a list endpoint without `limit`/`cursor`.
* `postman` writes a Postman v2.1 collection (one folder per tag, `{{baseUrl}}` and
  `{{token}}` variables).

`scripts/openapi/generate_clients.sh` runs all three and then generates TypeScript, Python
and Go clients with `openapi-generator`.

## Redoc

`redoc_html(title, spec_url)` returns a standalone Redoc page. Serve it next to Swagger UI:

```rust
.route("/redoc", get(|| async { axum::response::Html(rest_api::redoc_html("Perigee API", "/api-docs/openapi.json")) }))
```

## Contract tests in CI

`.github/workflows/openapi-contract.yml` runs the tooling tests on every change under `core/`,
and, when `docs/openapi/openapi.json` (a committed snapshot of the served spec) exists, runs
`prepare`, `check` and `postman` on it. Refresh the snapshot whenever endpoints change.
